## 二、体验增益(🟢 用户每天都感觉得到)

### B1. 一键诊断面板 🩺
**为什么**:现在用户反馈「连点没反应」,你要来回问一堆信息(窗口模式?发送方式?最小化?)。把这些固化成界面上的一个按钮。

**做什么**:「帮助 → 一键诊断」弹出一个报告页:
- 当前选中窗口的:标题 / 类名 / 是否可见 / 是否最小化 / 是否 UWP 宿主(`ApplicationFrameHost`)/ DPI / 是否全屏独占
- 连点器当前:发送方式 / 最近 10 次点击的成功与失败数 / 失败原因
- 直接给出**可操作建议**(「该窗口是 UWP 容器,请改用 CoreWindow 子窗口」)

**验收**:任意一个「点了没反应」的窗口,点诊断按钮后能在 5 秒内说出原因。

### B2. 连点失败自动降级 + 提示 🔧
**为什么**:`auto` 模式用 `PostMessage` 返回值判定成功,但返回 TRUE 只代表消息进了队列 —— 全屏独占 / UIPI 跨完整性级别会静默丢弃。用户看到「运行中 + 点击数在涨」,其实游戏什么都没收到。

**做什么**:连续 N 次(建议 20)投递后**回环验证**(读一次窗口状态 / 或对比帧差),确认无效就:
- 状态栏 + 卡片标红提示「后台投递无效,建议切到 send 真实输入」
- 提供一键切换(而不是让用户自己去设置里翻)

**依赖**:需要每个游戏一个可靠的「生效判据」。MVP 可以先用**用户确认**(弹一次「这样点有用吗?」记住选择)。

### B3. 挂机时段支持「跨天 + 多段」 📅
**为什么**:现在只有一段 `start → end`,且**起止相同会被当成全天**(语义歧义)。真实用户要的是「22:00-02:00 挂 A 游戏,10:00-12:00 挂 B 游戏」。

**做什么**:
- 支持多条时段(列表),每条可指定「暂停 / 停止」动作
- 起止相同 → **明确提示**「这是 0 分钟时段,是否想设全天?」而不是默默当全天
- 支持「工作日 / 周末」分组(复用 scheduler 已有的 weekly 逻辑)

### B4. 宏编辑器可视化 🎬
**为什么**:键盘宏现在只能录/放,不能改。用户想「把录好的宏里某一步延时从 100ms 改成 500ms」只能重录。

**做什么**:一个表格编辑器(步骤 / 类型 / 键 / 延时 / 注释),支持:
- 拖拽排序、插入延时、删除
- **循环段标记**(把 3-7 步标成循环体,重复 N 次)—— 这是录制做不到的
- 实时预览时间轴总长

**验收**:能纯手工编出一个「按 5 次 E,等 2 秒,Shift+点击,循环」的宏并回放。

### B5. 连点器「条件触发」 ⚡
**为什么**:很多挂机游戏是「有 CD 了就点」。纯定时连点会在 CD 中空烧,还可能被检测。

**做什么(MVP 版)**:点位加一个「像素变色触发」选项 ——
- 记录点位时同时存一个「期望颜色」+ 容差
- 每次轮询先取该点像素,**变了才点**
- 用 `preview_capture` 已有的 GDI 抓帧实现,不引入新依赖

**验收**:在 Melvor Idle 这类有 CD 条的游戏上,CD 好了才点,CD 中不点。

## 三、新能力(🔵 有意思且真有用)

### C1. 挂机报告 / 周报 📊
**为什么**:统计现在只有「运行时长 / 点击数」,用户看不到「我这一周挂了多少」。

**做什么**:
- 按天聚合:每窗口运行时长、点击/按键数、掉线次数、自动重启次数
- 一张表 + 一张折线(可用 QtCharts,或导 CSV 让用户自己画)
- **导出 Markdown / CSV**,方便发群友

**依赖**:`statistics.py` 已有计数,补一个按天分桶的存储。

### C2. 配置方案(Profile)切换 🎛️
**为什么**:用户常用场景是「晚上挂 5 个号用 A 套点位,白天挂 2 个号用 B 套」。现在只能手改。

**做什么**:把「全部窗口的连点/宏配置 + 启停状态」存成一个命名方案,一键切换。和现有 `backup.py` 的区别是:**方案是轻量的、可快速切换的**,备份是整包归档。

### C3. 窗口健康度评分 ❤️
**为什么**:多开最怕「某个号悄悄掉线了不知道」。

**做什么**:每张卡片一个健康分(0-100),综合:
- 进程存活 / 窗口可见 / 预览能抓到帧 / 连点器在跑 / 无连续失败
- 低于阈值 → 托盘气泡 + 卡片黄/红边框
- 「健康度排行」一眼看出哪个号有问题

### C4. 老板键增强 🕶️
**为什么**:现在只有急停(Ctrl+Alt+P)。挂机党真正怕的是**有人过来时屏幕上还开着这个软件**。

**做什么**:
- 老板键:一键「隐藏全部窗口 + 静音 + 暂停所有自动化」,再按一次还原
- 记住「隐藏前的状态」,还原时精确恢复(不是一律全启)
- 可选:隐藏时把嵌入的游戏窗口也弹出还原到原位置

### C5. 脚本市场 / 预设分享 🔗
**为什么**:内置 10+ 预设,但每个游戏的最佳实践靠用户自己摸索。

**做什么**:
- 导出的预设 JSON 带「游戏名 / 适用窗口标题正则 / 作者备注」
- 「工具 → 导入预设」支持从剪贴板 / 文件批量导入
- 远期:社区仓库(用户自愿上传),本地只做索引和下载

**注意**:这条要谨慎 —— **不要**自动上传任何用户数据(现在已经是 100% 本地,这个底线要守住)。

### C6. 宏录制支持「相对窗口」而非「相对屏幕」 📍
**为什么**:现在 `macro_recorder` 用「录制时第一个鼠标事件坐标」当窗口原点,而录制时鼠标可能根本不在目标窗口内(先在桌面点一下再进游戏)→ **回放整体偏移一个荒谬距离**。

**做什么**:录制开始时显式抓一次 `client_origin` 存进 `MacroScript`;回放时用**当前的** `client_origin` 做基准。窗口换了分辨率 / 换了显示器都能打对。

**依赖**:这是审计里 P2-7,属于「顺带修掉且直接提升可用性」。
